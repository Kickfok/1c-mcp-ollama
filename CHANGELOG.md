## [1.4.0] - 2026-10-11

Модель отвечает данными базы: читает таблицы по описанию в JSON, находит записи за период, формирует
готовые отчеты БСП и читает журнал регистрации. Когда вопрос задан из формы 1С, инструменты
выполняются в сеансе этого пользователя, поэтому действуют его роли и ограничения на уровне записей.
Проверено платформой 8.3.27 на копии 1С:Комплексная автоматизация 2 с реальной Ollama
(`qwen2.5-coder:32b`, RTX 5070 12 ГБ): 22 проверки инструментов данных через HTTP-сервис, 11 проверок
выполнения в сеансе пользователя, 17 проверок инструментов запросов, вопросы из формы, 36 тестов
оркестратора.

### Добавлено

- Инструменты выполняются в сеансе пользователя. Форма отправляет вопрос с `tool_mode: "client"`,
  оркестратор ставит вызов инструмента в очередь вопроса (`pending_tool` в `GET /requests/{id}`), форма
  выполняет его на сервере 1С через `mcp_Выполнение.ВызватьИнструментMCP` и возвращает результат
  (`POST /requests/{id}/tool_result`). Привилегированный режим в этом случае не включается, роли и RLS
  применяет платформа. В ходе выполнения такие вызовы отмечены `1С CALL`.
- Контейнер "Данные базы" (`mcp_ИнструментДанныеБазы`) с пятью инструментами, описанными ниже.
- `read_table`: таблица по описанию в JSON - поля, отборы (`=`, `<>`, `>`, `>=`, `<`, `<=`, `in`,
  `contains`), группировка с периодичностью (`Дата:month`), итоги (`sum`, `count`, `countDistinct`,
  `max`, `min`, `avg`), порядок, период, `maxRows` и `offset`. Для регистров период уходит в параметры
  виртуальных таблиц `Остатки`, `Обороты`, `ОстаткиИОбороты`, `СрезПоследних`.
- `data_profile`: в каких документах и регистрах есть записи за период, сколько их и за какие даты.
  Таблицы проверяются пачками по 40 через `ОБЪЕДИНИТЬ ВСЕ`, обход ограничен 15 секундами и
  продолжается по `offset`. При заданном периоде таблицы без даты записи не проверяются, об этом
  сообщает `note`.
- `read_event_log`: журнал регистрации по периоду, уровню, событию, пользователю и тексту, режим
  `summary` считает события. Нужно право "Журнал регистрации".
- `list_report_variants` и `run_report_variant`: поиск вариантов отчетов БСП по словам вопроса и
  формирование варианта с периодом, отборами и параметрами. Результат - записи из данных расшифровки
  с заголовками колонок отчета; пустой отчет помечается периодом, за который он сформирован.
- Финальный ответ модели с полем `ResultFrom`: модель пишет вывод и называет инструмент, оркестратор
  подставляет полный результат этого инструмента. Если модель не назвала инструмент и не дала свой
  `Result`, подставляется последняя полученная таблица.
- В промпте текущая дата: вопросы "за этот год" и "за прошлый месяц" модель переводит в правильный
  период.
- `run_query` возвращает результаты всех запросов пакета (`batchResults`) и пропускает строки по
  `offset`.
- Неизвестное имя параметра инструмента отклоняется со списком допустимых имен.
- `get_metadata_structure` сворачивает однотипные поля: `Часов1 ... Часов31 (31 полей с номерами 1-31)`.
- Схема "Как это работает" и история версий с планом развития в README.

### Изменено

- Обработки `mcp_ИнструментДанныеПродаж` и `mcp_ИнструментДляБухгалтерскойРаботы` выведены из
  подсистемы `mcp_КонтейнерыИнструментов`: 15 из 16 их инструментов возвращали фиксированные
  демонстрационные данные, и модель пересказывала их как настоящие. Обработки остались в расширении как
  образец. Инструментов 13, все читают базу. Промпт первого шага сократился с 2 898 до 2 227 токенов
  из 4 096.
- Движок запросов модели вынесен в общий модуль `mcp_ЗапросыМодели`, общее ядро вызова инструмента - в
  `mcp_Выполнение.ВызватьИнструментMCP`.
- Ответ инструментов данных - единая таблица `columns`, `rows`, `rowCount`, `totalRows`, `truncated`,
  `note`; форма выводит ее с русскими заголовками и строкой "Показано строк: X из Y".
- Файл расширения в релизе - `1C-MCP-Ollama-Bridge-<версия>.cfe`, синоним расширения - "1C MCP Ollama
  Bridge". Имя расширения `MCP_Сервер` не изменилось.
- Вопрос "Какие реквизиты у документа "Перемещение товаров"?" - 1 мин вместо 8 мин 41 с, "Какие
  документы делают движения по регистру ТоварыНаСкладах?" - 1 мин 10 с вместо 6 мин 21 с: модель
  больше не переписывает данные в ответ.
- Инструментов 13: обновлены [docs/TOOLS.md](docs/TOOLS.md) и [docs/api/openapi.json](docs/api/openapi.json).

### Исправлено

- `УстановитьПривилегированныйРежим(Ложь)` без предшествующего включения вызывал ошибку, когда вопрос
  задан без токена; режим теперь выключается только там, где был включен.
- Поиск ссылки по строке в параметрах запроса менял значение аргумента и падал с "Поле объекта
  недоступно для записи".

### Обновление

- С 1.3.0: замените расширение и `LLM_Orchestrator.py` из архива релиза, файл конфигурации с ключами
  не меняйте. Старый оркестратор не знает `tool_mode: "client"`: обновляйте оба компонента вместе.
- Если вы пользовались инструментами продаж и бухгалтерии, верните обработку в подсистему
  `mcp_КонтейнерыИнструментов` в своей копии расширения.

### Известные ограничения

- Готовые отчеты формируются только из формы 1С: через публикацию выражения схем компоновки
  выполняются с правами пользователя публикации и падают с нарушением прав.
- Через публикацию (внешние MCP-клиенты) RLS не применяется: права на таблицы проверяются по ролям
  владельца токена, данные читает сеанс публикации.

## [1.3.0] - 2026-10-10

Модель отвечает на вопросы о данных, для которых нет готового инструмента: она сама пишет запрос 1С,
а сервер проверяет права пользователя на каждую таблицу запроса. Администратор может передать модели
заметки о базе. Проверено платформой 8.3.27 на копии 1С:Комплексная автоматизация 2 с реальной Ollama
(`qwen2.5-coder:32b`, RTX 5070 12 ГБ): 17 проверок инструментов запросов через HTTP-сервис, сквозные
вопросы под пользователем с правами и без прав, 28 тестов оркестратора.

### Добавлено

- Инструмент `run_query`: выполняет запрос на языке 1С, который составила модель. Ко всем запросам
  пакета добавляется `РАЗРЕШЕННЫЕ`, результат ограничен `maxRows` строками (по умолчанию 20, до 500) и
  возвращается колонками и строками (`columns`, `rows`, `rowCount`, `truncated`). Значения из `parameters`
  приводятся к типам параметров запроса: даты и числа из строк, ссылки по идентификатору,
  наименованию, коду или номеру, значения перечислений по имени.
- Инструмент `validate_query`: разбирает текст запроса через `СхемаЗапроса` и проверяет права, данные не
  читает. Ошибка разбора дополняется подсказкой про агрегатные функции и `СГРУППИРОВАТЬ ПО`.
- Права в `validate_query` и `run_query` проверяются для пользователя, задавшего вопрос: право "Чтение"
  на каждую таблицу, на таблицы вложенных запросов и на объекты полей, прочитанных через точку
  (`Т.Контрагент.ИНН`, с учетом составных типов). Таблицы определяются по тексту запроса без строк и
  комментариев.
- Инструмент `find_report_queries`: находит в основных схемах компоновки отчетов конфигурации запросы
  по словам вопроса и возвращает до трех образцов. Тексты запросов собираются один раз за сеанс
  (`mcp_КонтейнерыПовтИсп.ЗапросыОтчетов`), просматриваются только отчеты, доступные пользователю.
- Заметки для модели: вкладка "Заметки для модели" в настройках, до 1500 символов. Заметки
  передаются оркестратору полем `instructions` вопроса и добавляются в промпт на каждом шаге, внешние
  MCP-клиенты получают их в поле `instructions` ответа `initialize`.
- Форма вопроса выводит результат `run_query` таблицей с колонками запроса и числом строк.

### Изменено

- Системный промпт: если готового инструмента нет, модель составляет запрос через
  `get_metadata_structure`, `find_report_queries`, `validate_query` и `run_query`. Промпт отделяет
  описание конфигурации от записей базы: вопрос о записях требует `run_query`.
- После ответа `get_metadata_structure` и `list_metadata_objects` в промпт добавляется подсказка: это
  описание конфигурации, для вопроса о записях нужен `run_query`. Вопрос "Выведи список пользователей
  базы" раньше занимал 8 минут (модель переписывала структуру справочника в ответ), теперь 2 мин 10 с.
- На шагах после первого промпт содержит краткий список инструментов (имя и параметры, обязательные
  отмечены `*`): модель меньше ошибается в именах параметров.
- После ошибки инструмента модель получает указание исправить аргументы и не выдумывать данные.
  Повторный вызов с теми же аргументами возвращает подсказку изменить аргументы или дать ответ.
- Оркестратор принимает аргументы инструмента, которые модель положила рядом с `action`, а не в
  `arguments`.
- Инструментов 24: обновлены [docs/TOOLS.md](docs/TOOLS.md) и [docs/api/openapi.json](docs/api/openapi.json).

### Исправлено

- Защита от зацикливания в оркестраторе не срабатывала: повтор вызова отклонялся раньше, чем
  увеличивался счетчик, и модель доходила до лимита в 15 шагов. Теперь три отклоненных повтора подряд
  завершают вопрос ошибкой `loop_detected`.
- `list_metadata_objects` искал маску `*Контрагент*` как подстроку вместе со звездочками и возвращал
  пустую строку. Символы `*` и `%` из маски убираются, при пустом результате инструмент сообщает, что
  объекты не найдены.
- Строка над ответом после закрытия настроек показывала время до текущего момента, а не время
  получения ответа.

### Обновление

- С 1.2.1: замените расширение и `LLM_Orchestrator.py` из архива релиза, файл конфигурации с ключами
  не меняйте.
- Ограничения на уровне записей (RLS) к `run_query` не применяются: данные читает сеанс публикации.
  Если в базе они настроены, проверьте состав группы доступа с ролью "Вопросы к LLM по данным базы
  (MCP)".

## [1.2.0] - 2026-10-05

Форма вопроса работает в двух режимах: серверном и локальном с автозапуском Ollama и оркестратора из
тонкого клиента. Вместе с 1.2.0-beta - ключи оркестратора, токены пользователей 1С с проверкой прав,
настройки и диагностика в 1С. Проверено платформой 8.3.27: полный цикл в обоих режимах на копии
1С:Комплексная автоматизация 2 (БСП 3.1.11) и на 1С:Управление торговлей 11.5 (установка, карточки
"не настроено", серверный и локальный режимы, остановка запроса), тесты оркестратора, интеграционные
тесты через внешнее соединение.

### Добавлено

- Форма вопроса работает в двух режимах. Серверный: вопрос отправляет сервер 1С оркестратору из
  "Настройки". Локальный: Ollama и оркестратор работают на компьютере пользователя, запросы к ним
  выполняет тонкий клиент, токены и разбор ответов остаются на сервере.
- Автозапуск в локальном режиме после вопроса пользователю: скрипт оркестратора и файл конфигурации
  `LLM_Orchestrator.1c.config.json` (адрес публикации MCP, личный ключ, порт, Ollama на 127.0.0.1)
  записываются в каталог из "Мои настройки" или во временный, проверяется пакет `requests` с
  предложением установить его, Ollama запускается, только если не отвечает.
- Кнопка "Остановить"; запрос останавливается и при закрытии формы, через минуту без связи с
  оркестратором и по "Таймаут ответа".
- Карточка на стартовом экране, когда вопрос задать нельзя: подключение не настроено, локальный режим в
  веб-клиенте, безопасный режим расширения. Администратору форма сама открывает "Настройки",
  пользователю с незаполненным локальным режимом - "Мои настройки".

### Изменено

- Форма больше не запускает программы на сервере 1С и не использует фоновое задание: удалены запуск
  через `ЗапуститьПриложение`, проверка процессов через WMI, каталог `C:\llm_orchestrator\` и переключатель
  "Подключение на Сервере".
- `mcp_ОркестраторLLM.АдресМонитора` принимает адрес оркестратора; удалены `ОтправитьВопросВФоне` и
  `СобытияЗапроса`. `ОтправитьВопрос` оставлен для интеграций, которым нужен ответ одним вызовом.

### Исправлено

- Ход выполнения в форме терял последние события: состояние запроса теперь читается раньше журнала.
- Запрос, о котором оркестратор не знает (оркестратор перезапускали), завершается понятной ошибкой, а не
  ожиданием без конца.

### Обновление

- С 1.2.0-beta: замените расширение. Каталог `C:\llm_orchestrator\` больше не используется; локальный
  режим настраивается в "Мои настройки" (docs/INSTALL.md, раздел 7).
- С 1.1.0: дополнительно снимите безопасный режим расширения, выдайте роли (`mcp_ОсновнаяРоль` -
  пользователю публикации, `mcp_ИспользованиеLLM` - через профиль групп доступа), переведите публикацию
  на технического пользователя, запустите оркестратор с `--config` и укажите в "Настройки" адрес и
  `client_key`.

### Известные ограничения

- Локальный режим работает только в тонком клиенте: в веб-клиенте нет исходящих соединений с компьютера
  пользователя.
- Ограничения доступа на уровне записей (RLS) не применяются: проверяются права на объекты метаданных.

веб-клиент, живой прогон с qwen2.5-coder:32b.

### Безопасность

- Оркестратор принимает запросы только с ключом (`Authorization: Bearer`): ключ клиента для 1С и ключ
  администратора для монитора и общего журнала. Ключи создаются при первом запуске и хранятся в файле
  конфигурации `--config`; ключ короче 32 символов - отказ запуска; подбор ключа ограничен (429).
- Ключ клиента читает журнал только своего вопроса; монитор и список вопросов - по ключу
  администратора, вход в монитор по ключу или одноразовому билету `--monitor`.
- HTTPS оркестратора: `tls_cert` и `tls_key`.
- Токен пользователя 1С (`X-MCP-Token`): форма выпускает его на время вопроса, оркестратор передает во
  все вызовы инструментов, HTTP-сервис проверяет права этого пользователя - объекты без прав скрываются,
  запрос их структуры и данных отклоняется (ошибка JSON-RPC `-32001`). Вызов без токена разрешается или
  запрещается в настройках. В базе хранится только SHA-256 токена.
- Персональные токены для внешних MCP-клиентов (Cursor, Claude Desktop) выпускает администратор.
- Ключ серверного оркестратора хранится в безопасном хранилище БСП и не возвращается ни клиенту, ни
  во внешнее соединение.
- Клиенту и модели ошибки HTTP-сервиса и инструментов отдаются кратко, стек вызовов - в журнал
  регистрации (`MCP.ОшибкаHTTPСервиса`, `MCP.ОшибкаИнструмента`).

### Добавлено

- Формы "Настройки подключения к LLM" (администратор: адрес и ключ оркестратора, доступ к MCP,
  пользователи с локальным режимом, персональные токены) и "Мои настройки LLM".
- Диагностика из 10 проверок с HTML-отчетом и подсказками: права, безопасный режим, ключ, доступность
  оркестратора, ключ принят, Ollama и модель, связь с MCP, сквозной вызов инструмента с токеном, защита
  канала, пользователь публикации.
- Оркестратор: асинхронный API (`POST /requests`, `GET /requests/{id}`, отмена), пользователь 1С в
  событиях журнала, `POST /diagnostics`, подробный `/health` с состоянием Ollama и MCP, файл конфигурации.
- Описание HTTP-сервиса по OpenAPI 3.0 (`docs/api/openapi.json`, `tools/gen_openapi.py`) и для
  расширения swagger-1c (модуль `mcp_APIBackendОписание`).
- Роль `mcp_ИспользованиеLLM` для пользователей, задающих вопросы.
- Скрипт `tools/build_extension.ps1`: загрузка, проверка модулей, обновление базы, сборка `.cfe`.
- Тесты оркестратора `tests/test_orchestrator.py` в CI.

### Изменено

- Нужна конфигурация на БСП 3.1+: ключи хранятся в безопасном хранилище БСП, пользователи и права -
  средствами БСП. Из БСП используется только программный интерфейс.
- Публикация HTTP-сервиса должна работать под техническим пользователем без полных прав.

### Исправлено

- Логотип в форме "Анализ конфигурации MCP" выводился без градиентов и надписи "1C": поле HTML
  тонкого клиента на Windows рисует встроенный SVG с ошибками. Логотип в макете `ОформлениеОтвета`
  заменен на PNG в base64.

### Обновление с 1.1.0

- Снимите безопасный режим расширения, выдайте роли (`mcp_ОсновнаяРоль` - пользователю публикации,
  `mcp_ИспользованиеLLM` - через профиль групп доступа), перенастройте публикацию на технического
  пользователя.
- Запустите оркестратор с `--config`, затем в "Настройки" укажите адрес и `client_key`.

### Известные ограничения

- Форма вопроса прежняя: вопрос уходит по адресу и ключу из настроек, а автозапуск из формы
  выгружает оркестратор в `C:\llm_orchestrator\` без вашего файла конфигурации - скопируйте
  `client_key` из созданного там `LLM_Orchestrator.config.json` в настройки (см. docs/INSTALL.md, раздел 7).
- Локальный режим работает в тонком клиенте; в веб-клиенте форма сообщает об этом.
- Ограничения доступа на уровне записей (RLS) не применяются: проверяются права на объекты метаданных.

## [1.1.0] - 2026-10-04

Форма 1С с ответом в HTML и ходом выполнения в реальном времени, монитор оркестратора, реальные
прогоны в README. Проверено платформой 8.3.27 на копии 1С:Комплексная автоматизация 2 (2.5.25.109)
в тонком и веб-клиенте.

### Добавлено

- Монитор оркестратора `GET /monitor`: запросы, шаги модели с временем и заполнением контекста,
  вызовы инструментов 1С с аргументами и ответами, итоговый JSON; темная и светлая тема. Ключ
  `--monitor` и переменная `ORCHESTRATOR_MONITOR=1` открывают его отдельным окном после запуска.
- Журнал событий оркестратора: `GET /events`, `GET /health`, `GET /tools`. Ответ `POST /` содержит
  `RequestId` и `Trace` - ход выполнения запроса. Клиент может передать свой `request_id`.
- Переменная `OLLAMA_NUM_GPU`: число слоев модели на видеокарте.
- Форма "Анализ конфигурации MCP": ответ в поле HTML в светлом оформлении проекта, ход выполнения в
  реальном времени (вопрос уходит в фоновое задание, форма раз в секунду читает журнал оркестратора),
  данные `Result` таблицами и списками, примеры вопросов на стартовом экране, кнопка монитора.
- Общий модуль `mcp_ОркестраторLLM`, макет `ОформлениеОтвета`.
- README: реальные прогоны пяти инструментов конфигурации на копии 1С:Комплексная автоматизация 2.

### Изменено

- Оркестратор обрабатывает запросы в нескольких потоках: монитор и форма читают журнал, пока модель
  отвечает на вопрос.
- Оркестратор повторяет запрос к Ollama при ошибке 5xx: runner Ollama иногда падает при
  загрузке модели с `CUDA error`.
- Форма в безопасном режиме расширения показывает, как его снять, вместо ошибки фонового задания.

### Исправлено

- Форма теряла вопрос, если кнопку нажимали сразу после ввода или по Ctrl+Enter: текст еще не был
  перенесен из поля в реквизит формы.
- `docs/INSTALL.md` утверждал, что форма отправляет вопрос оркестратору в безопасном режиме
  расширения. В этом режиме платформа запрещает `HTTPСоединение`, таблица исправлена.

## [1.0.0] - 2026-10-04

Первая публикация. Исходники расширения выгружены из рабочей версии `MCP_Сервер.cfe` и исправлены;
все исправления проверены платформой 8.3.27 и запросами к опубликованному HTTP-сервису.

### Добавлено

- LLM-оркестратор: переменные окружения `MCP_URL`, `MCP_VERIFY_SSL`, `OLLAMA_URL`, `OLLAMA_MODEL`,
  `ORCHESTRATOR_HOST`, `ORCHESTRATOR_PORT`.
- Права роли `mcp_ОсновнаяРоль`: использование методов HTTP-сервиса и обработок, просмотр подсистемы.
  Раньше роль была пустой, и пользователь без полных прав получал отказ в доступе.
- Функция `mcp_ОбщегоНазначения.ДатаИзСтроки` для дат в формате `ГГГГ-ММ-ДД`.
- Журнал регистрации: ошибки обработок-контейнеров пишутся событием `MCP-сервер.Контейнеры`.
- `tests/mcp_smoke.py` - проверка опубликованного MCP-сервера; `tools/check_sources.py` - статические
  проверки исходников; `tools/sync_orchestrator.py` - синхронизация макета `LLM_Orchestrator`;
  `tools/gen_tools_doc.py` - генерация `docs/TOOLS.md`; проверки в GitHub Actions и публикация
  релиза по тегу `vX.Y.Z`.
- Документация: README, установка, описание инструментов, разработка инструментов.

### Изменено

- Расширение больше не требует БСП и БТС. Вызовы `ОбщегоНазначенияКлиентСервер.ЕстьРеквизитИлиСвойствоОбъекта`
  (9), `ОбщегоНазначения.ЗначениеРеквизитаОбъекта` (1) и `ОбщегоНазначенияБТС.Пауза` (1) заменены
  собственным кодом. В конфигурации без БСП модуль `mcp_ИнструментДанныеОКонфигурации` не компилировался,
  и `tools/list` возвращал HTTP 500.
- Ошибка одной обработки-контейнера больше не прерывает `tools/list`: контейнер пропускается.
- Форма "Анализ конфигурации MCP" сначала отправляет запрос оркестратору и запускает Ollama и оркестратор,
  только если он не ответил; в безопасном режиме расширения выводит подсказку вместо ошибки.
  У соединения с оркестратором задан таймаут 1800 секунд. Пауза 100 мс перед запросом удалена:
  оркестратору после запуска нужно больше минуты, форма просит повторить запрос.
- Оркестратор по умолчанию принимает запросы только на `127.0.0.1`, а не на всех интерфейсах:
  у него нет авторизации.
- Идентификаторы JSON-RPC запросов оркестратора к MCP-серверу уникальны в пределах запуска.
- Версия расширения: 1.0.0.

### Исправлено

- `list_sale_param`: дата `ГГГГ-ММ-ДД` вызывала ошибку "Преобразование значения к типу Дата не может
  быть выполнено"; дата окончания периода теперь включает весь день.
- `list_object_dependencies`: тип объекта определялся по имени (`Метаданные.Документы.Найти(ОбъектМД.Имя)`),
  справочник с именем документа ломал анализ. Теперь проверка через `Содержит()`. Связь "регистратор"
  для регистров находится через движения документов; прежняя ветка по несуществующему свойству
  `Регистраторы` не срабатывала никогда.
- Представления с несуществующим кодом языка `ru1` (35 мест): у двух обработок-контейнеров был пустой
  синоним, на форме анализа не отображались заголовки и подсказки.
- Синоним подсистемы "MCP-сервер" содержал латинскую букву `c`.
- Оркестратор: обработчик ошибки отправки ответа обращался к несуществующему атрибуту `headers_sent`;
  тело запроса не в UTF-8 возвращало 500 вместо 400.
- Повторяющееся значение `CommonModules` в списке допустимых значений `metaType`.

### Удалено

- Диагностическая запись в журнал регистрации при каждом `tools/list` (по одной записи на инструмент).
- Команда формы "Заполнить описание методов" без обработчика.

### Известные ограничения

- 15 из 21 инструмента - заглушки с фиксированными данными (см. README).
- Модель получает список инструментов только на первом шаге диалога: так промпт укладывается
