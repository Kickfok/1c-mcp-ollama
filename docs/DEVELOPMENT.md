# Разработка инструментов

## Как сервер находит инструменты

При вызове `tools/list` модуль `mcp_Метаданные` обходит состав подсистемы
`mcp_MCPСервер.mcp_КонтейнерыИнструментов` и у каждой обработки вызывает метод модуля менеджера
`ДобавитьИнструменты`. Результат кешируется на сеанс в `mcp_КонтейнерыПовтИсп`. Ресурсы и промпты
устроены так же: подсистемы `mcp_КонтейнерыРесурсов` и `mcp_КонтейнерыПромптов`, методы
`ДобавитьРесурсы` и `ДобавитьПромпты`.

Если метод контейнера завершается ошибкой, контейнер пропускается, а причина записывается в журнал
регистрации событием `MCP-сервер.Контейнеры`. Инструменты остальных контейнеров остаются доступны.

## Новый контейнер инструментов

1. Создайте в расширении обработку с префиксом `mcp_` и включите ее в подсистему
   `mcp_КонтейнерыИнструментов`. Синоним обработки попадет в поле `container` ответа `tools/list`.
2. Добавьте обработке право `Использование` в роли `mcp_ОсновнаяРоль`.
3. Реализуйте в модуле менеджера два экспортных метода:

```bsl
Процедура ДобавитьИнструменты(Инструменты) Экспорт
	
	Параметры = Новый Массив;
	Параметры.Добавить(mcp_Метаданные.ПараметрИнструмента(
		"name", "string", "Имя справочника", , Истина));
	Параметры.Добавить(mcp_Метаданные.ПараметрИнструмента(
		"maxItems", "number", "Максимальное количество элементов", 50));
	
	mcp_Метаданные.ДобавитьИнструмент(
		Инструменты,
		"get_catalog_items",
		"Список элементов справочника",
		mcp_Метаданные.СхемаПараметровИнструмента(Параметры));
	
КонецПроцедуры

Функция ВыполнитьИнструмент(ИмяИнструмента, Аргументы) Экспорт
	
	Если ИмяИнструмента = "get_catalog_items" Тогда
		Возврат ЭлементыСправочника(Аргументы);
	Иначе
		ВызватьИсключение "Неизвестный инструмент: " + ИмяИнструмента;
	КонецЕсли;
	
КонецФункции
```

`ВыполнитьИнструмент` возвращает строку, массив элементов содержимого
(`mcp_Содержимое.ТекстовоеСодержимое`, `ИзображениеСодержимое`) или любое значение, которое сервер
преобразует в текст. Исключение превращается в ответ с `isError: true` и текстом ошибки - модель
видит его и может исправить аргументы.

## Как вызывается инструмент

Оба пути вызова сходятся в `mcp_Выполнение.ВызватьИнструментMCP(ИмяИнструмента, Аргументы,
КонтекстДоступа)`: он находит контейнер, отклоняет неизвестные имена параметров со списком
допустимых, пишет вызов в журнал токенов и превращает исключение в результат с `isError: true`.

| Путь | Кто вызывает | Контекст доступа |
|---|---|---|
| Внешний MCP-клиент или оркестратор без `tool_mode` | HTTP-сервис `mcp_APIBackend`, `tools/call` | токен `X-MCP-Token`: права владельца токена, чтение в привилегированном режиме сеанса публикации |
| Форма вопроса | `mcp_ОркестраторLLM.СостояниеВопроса` при опросе `pending_tool` | `mcp_ДоступПользователей.КонтекстСеансаПользователя()`: текущий сеанс, роли и RLS пользователя |

Инструмент не должен различать эти пути сам: права проверяйте через `mcp_ДоступПользователей`, он
учитывает контекст.

## Правила для инструментов

- Проверяйте аргументы через `Свойство()`. Модель может не передать обязательный параметр, и
  `Аргументы.name` без проверки дает невнятное "Поле объекта не обнаружено".
- Даты разбирайте функцией `mcp_ОбщегоНазначения.ДатаИзСтроки`. Модель передает даты строкой
  `ГГГГ-ММ-ДД`, а `Дата("2024-03-01")` платформы завершается ошибкой.
- Ограничивайте объем ответа параметром `maxItems` или аналогичным. Оркестратор обрезает ответ
  инструмента до 2500 символов, чтобы уложиться в контекст модели 4096 токенов.
- Перед чтением объекта проверяйте права пользователя, задавшего вопрос:
  `mcp_ДоступПользователей.ДоступноПользователю(Аргументы, ОбъектМетаданных)`. Через публикацию
  инструмент работает в сеансе ее пользователя, и без этой проверки модель получит данные, закрытые для
  пользователя. Из формы 1С тот же вызов проверяет права текущего сеанса. Так устроены `validate_query`,
  `run_query` и `read_table`: они проверяют каждую таблицу запроса до выполнения. Другие права
  проверяет `mcp_ДоступПользователей.ЕстьПравоПользователя(Аргументы, Право, ОбъектМетаданных)`.
- Привилегированный режим включайте только при токене пользователя и выключайте только если включили:
  `УстановитьПривилегированныйРежим(Ложь)` без предшествующего включения в сеансе пользователя
  вызывает ошибку.

  ```bsl
  Привилегированно = mcp_ДоступПользователей.ЕстьТокенПользователя(Аргументы);
  Если Привилегированно Тогда
  	УстановитьПривилегированныйРежим(Истина);
  КонецЕсли;
  ```

- Табличный результат возвращайте в едином формате `columns`, `rows`, `rowCount`, `totalRows`,
  `truncated` и, если нужно пояснение, `note`. Форма выводит такую структуру таблицей, а модель может
  передать ее в ответ целиком через `ResultFrom`. Запросы выполняйте через
  `mcp_ЗапросыМодели.ВыполнитьЗапрос`: он добавляет `РАЗРЕШЕННЫЕ`, проверяет права и ограничивает
  число строк.
- Из БСП вызывайте только программный интерфейс (`ОбщегоНазначения`, `Пользователи` и т.п.): служебные модули
  БСП (`*Служебный*`) не гарантируют совместимость между версиями, модулей БТС в конфигурации может не
  быть. Проверка `tools/check_sources.py` это контролирует. Объекты прикладной конфигурации (справочники,
  отчеты) читайте с проверкой наличия
  через `Метаданные.<Коллекция>.Найти(...)`, а тип объекта метаданных определяйте через `Содержит()`,
  а не по имени.
- Не возвращайте выдуманные данные. Если инструмент еще не реализован, пусть он вызывает исключение
  "не реализовано": модель сообщит об этом пользователю, а не перескажет цифры-заглушки.

## Проверка изменений

```powershell
# загрузка, проверка модулей во всех контекстах, обновление базы; -Dump - build/1C-MCP-Ollama-Bridge.cfe к релизу
$env:MCP_1C_PASSWORD = "<пароль>"   # если у пользователя есть пароль
powershell -File tools/build_extension.ps1 -Infobase "<каталог тестовой базы>" -User "<пользователь>"
python tools/check_sources.py
python -m unittest tests.test_orchestrator -v
python tests/mcp_smoke.py http://localhost/<публикация>/hs/mcp
python tools/gen_tools_doc.py http://localhost/<публикация>/hs/mcp > docs/TOOLS.md
python tools/gen_openapi.py --base http://localhost/<публикация>
```

Проверяйте на базе с конфигурацией на БСП 3.1+ и пользователем без полных прав: инструменты должны
скрывать объекты, на которые у него нет прав.
