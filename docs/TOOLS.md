### get_report_list

Получение списка отчетов конфигурации (встроенных и внешних) и их обязательных параметров. Внешние отмечаются как [Внешний отчет].

Внешние отчеты читаются из справочника ДополнительныеОтчетыИОбработки (БСП), если он есть в конфигурации.

| Параметр | Тип | Обязательный | По умолчанию | Описание |
|---|---|:---:|---|---|
| `reportName` | string |  |  | Имя или часть имени отчета для фильтрации (опционально). Проверяется вхождение в имя, синоним и наименование. |
| `includeDescription` | boolean |  | `False` | Включать описание отчетов |
| `source` | string |  | `All` | Источник отчётов: All - все, Configuration - только встроенные, External - только внешние (из справочника ДополнительныеОтчетыИОбработки) Допустимые значения: `All`, `Configuration`, `External`. |
| `includeParameters` | boolean |  | `False` | Читать обязательные параметры отчёта из его схемы компоновки данных (для конкретного отчёта по reportName). Для внешних отчётов работает только при выключенном безопасном режиме. |

### find_report_queries

Поиск готовых запросов в отчетах конфигурации: образец, по которому составить свой запрос для run_query

Запросы собираются из основных схем компоновки отчетов конфигурации один раз за сеанс HTTP-сервиса: первый вызов на 1С:КА 2 занимает около 10 с, следующие - доли секунды. Просматриваются только отчеты, доступные пользователю.

| Параметр | Тип | Обязательный | По умолчанию | Описание |
|---|---|:---:|---|---|
| `keywords` | string | да |  | Слова для поиска через пробел: имя регистра, документа или справочника, тема отчета (например: ТоварыНаСкладах остатки) |
| `maxItems` | number |  | `1` | Сколько запросов вернуть, от 1 до 3 |

### validate_query

Проверка запроса 1С без чтения данных: синтаксис, имена таблиц и полей, права пользователя. Возвращает таблицы, колонки результата и параметры запроса с типами

Разбирает текст через СхемаЗапроса, данные не читает. Проверяет право Чтение пользователя на каждую таблицу, на таблицы во вложенных запросах условий и на объекты полей, прочитанных через точку (Т.Контрагент.ИНН).

| Параметр | Тип | Обязательный | По умолчанию | Описание |
|---|---|:---:|---|---|
| `query` | string | да |  | Текст запроса на языке запросов 1С (ВЫБРАТЬ ... ИЗ ...), параметры задаются как &Имя |

### run_query

Выполнение запроса 1С только на чтение с правами пользователя: возвращает колонки и строки результата. Язык запросов 1С: ВЫБРАТЬ [ПЕРВЫЕ n] Т.Поле КАК Имя ИЗ Справочник.Имя КАК Т [ГДЕ ...] [СГРУППИРОВАТЬ ПО ...] [УПОРЯДОЧИТЬ ПО ...]; агрегаты КОЛИЧЕСТВО(), СУММА(), МАКСИМУМ(), МИНИМУМ()

Те же проверки прав, что у validate_query. Ко всем запросам пакета добавляется РАЗРЕШЕННЫЕ, результат ограничен maxRows строками, результаты остальных запросов пакета - в batchResults. Из формы 1С запрос выполняется в сеансе пользователя с его ограничениями на уровне записей (RLS); через публикацию RLS не применяется.

| Параметр | Тип | Обязательный | По умолчанию | Описание |
|---|---|:---:|---|---|
| `query` | string | да |  | Текст запроса на языке запросов 1С, проверенный через validate_query |
| `parameters` | object |  |  | Значения параметров &Имя, например {"НачалоПериода": "2026-01-01", "Склад": "Основной склад"}. Даты - ГГГГ-ММ-ДД, ссылку можно задать наименованием, кодом или номером документа |
| `maxRows` | number |  | `20` | Сколько строк результата вернуть, не больше 500 |
| `offset` | number |  |  | Сколько первых строк пропустить: следующая страница результата, если truncated = true |

### read_table

Чтение одной таблицы без языка запросов. Пример: {"table": "Документ.РеализацияТоваровУслуг", "fields": ["Номер", "Дата", "Контрагент"], "filters": [{"field": "Контрагент", "comparison": "=", "value": "Ромашка"}], "periodStart": "2026-03-01", "periodEnd": "2026-03-31"}. Итоги: "groupBy": ["Дата:month"], "aggregates": [{"field": "СуммаДокумента", "function": "sum"}]. Остатки: table РегистрНакопления.Имя.Остатки и periodEnd

Запрос строит сервер: модели не нужно знать язык запросов. Проверяется право Чтение на таблицу, к запросу добавляется РАЗРЕШЕННЫЕ. Ответ в формате run_query, текст построенного запроса - в поле query.

| Параметр | Тип | Обязательный | По умолчанию | Описание |
|---|---|:---:|---|---|
| `table` | string | да |  | Таблица: Справочник.Контрагенты, Документ.РеализацияТоваровУслуг, Документ.РеализацияТоваровУслуг.Товары (табличная часть), РегистрНакопления.ТоварыНаСкладах.Остатки, РегистрНакопления.Продажи.Обороты, РегистрСведений.КурсыВалют.СрезПоследних |
| `fields` | array of string |  |  | Поля результата, через точку - реквизит ссылки: ["Номер", "Дата", "Контрагент.ИНН"]. Пусто - все поля таблицы |
| `filters` | array of object |  |  | Отборы: [{"field": "Склад", "comparison": "=", "value": "Основной склад"}]. comparison: =, <>, >, >=, <, <=, in (value - массив), contains (подстрока). Ссылку задают наименованием, кодом или номером |
| `groupBy` | array of string |  |  | Группировка: ["Номенклатура"]; дату группируют по периоду: "Дата:month" (day, week, month, quarter, year) |
| `aggregates` | array of object |  |  | Итоги по группам: [{"field": "Сумма", "function": "sum"}]; function: sum, count, countDistinct, max, min, avg. Колонка итога называется по функции и полю: СуммаСумма |
| `order` | array of string |  |  | Порядок: ["Дата desc", "Номер"]; можно указывать колонки итогов |
| `periodStart` | string |  |  | Начало периода ГГГГ-ММ-ДД: отбор по дате документа или периоду регистра, параметр виртуальной таблицы |
| `periodEnd` | string |  |  | Конец периода ГГГГ-ММ-ДД включительно; для остатков и среза последних - дата, на которую они нужны |
| `maxRows` | number |  | `20` | Сколько строк вернуть, не больше 500 |
| `offset` | number |  |  | Сколько первых строк пропустить: следующая страница, если truncated = true |

### data_profile

Профиль данных базы: в каких документах и регистрах есть записи, сколько их и за какие даты. Помогает выбрать таблицу для read_table или run_query и не искать данные там, где их нет

Таблицы проверяются пачками по 40 одним запросом, обход ограничен 15 секундами; если проверены не все, ответ содержит nextOffset. При заданном периоде таблицы без даты записи (справочники, непериодические регистры сведений) не проверяются.

| Параметр | Тип | Обязательный | По умолчанию | Описание |
|---|---|:---:|---|---|
| `kinds` | array of string |  |  | Виды таблиц, по умолчанию все, кроме справочников; registers - все регистры |
| `words` | string |  |  | Слова через пробел: берутся таблицы, в имени или синониме которых есть хотя бы одно слово |
| `periodStart` | string |  |  | Начало периода ГГГГ-ММ-ДД: считаются записи с датой или периодом не раньше |
| `periodEnd` | string |  |  | Конец периода ГГГГ-ММ-ДД включительно |
| `maxTables` | number |  | `30` | Сколько таблиц с данными вернуть, самые заполненные первыми |
| `offset` | number |  |  | С какой таблицы продолжить обход: значение nextOffset прошлого ответа |

### read_event_log

Журнал регистрации 1С: ошибки, предупреждения и действия пользователей за период. Нужно право "Журнал регистрации" у пользователя, задавшего вопрос

Нужно право "Журнал регистрации". По умолчанию - последние сутки, не больше 10 000 событий за вызов.

| Параметр | Тип | Обязательный | По умолчанию | Описание |
|---|---|:---:|---|---|
| `periodStart` | string |  |  | Начало периода ГГГГ-ММ-ДД или ГГГГ-ММ-ДДTчч:мм:сс, по умолчанию сутки назад |
| `periodEnd` | string |  |  | Конец периода, по умолчанию сейчас |
| `levels` | array of string |  |  | Уровни событий |
| `event` | string |  |  | Часть имени события, например Данные.Изменение или Сеанс |
| `user` | string |  |  | Часть имени пользователя |
| `text` | string |  |  | Часть текста комментария или представления данных |
| `mode` | string |  | `records` | records - последние события, summary - сколько событий каждого уровня и вида Допустимые значения: `records`, `summary`. |
| `maxRows` | number |  | `20` | Сколько последних событий вернуть в режиме records |

### list_report_variants

Поиск готовых отчетов конфигурации по словам (выручка, остатки, задолженность). Отчет считает по методике конфигурации; ключ variant из ответа передается в run_report_variant

Ищет в справочнике ВариантыОтчетов (БСП) варианты внутренних отчетов и отчетов расширений с основной схемой компоновки, доступные пользователю.

| Параметр | Тип | Обязательный | По умолчанию | Описание |
|---|---|:---:|---|---|
| `search` | string |  |  | Слова через пробел: ищутся в названии варианта, описании и имени отчета, например "выручка продажи" |
| `maxItems` | number |  | `15` | Сколько вариантов вернуть |

### run_report_variant

Формирование готового отчета: {"variant": "<ключ>", "periodStart": "2026-01-01", "periodEnd": "2026-03-31"}; обязательные параметры отчета - в parameters. Возвращает записи отчета с названиями полей; пустой отчет помечен в note

Отчет формируется только из формы 1С, в сеансе пользователя: через публикацию выражения схемы компоновки выполняются с правами ее пользователя. Обязательные параметры отчета передаются в parameters.

| Параметр | Тип | Обязательный | По умолчанию | Описание |
|---|---|:---:|---|---|
| `variant` | string | да |  | Ключ variant из list_report_variants или точное название варианта |
| `periodStart` | string |  |  | Начало периода ГГГГ-ММ-ДД |
| `periodEnd` | string |  |  | Конец периода ГГГГ-ММ-ДД включительно |
| `filters` | array of object |  |  | Отборы отчета: [{"field": "Организация", "comparison": "=", "value": "Наше предприятие"}]. comparison: =, <>, >, >=, <, <=, in, contains |
| `parameters` | object |  |  | Параметры отчета по именам, например {"Пользователь": "Иванов"}; ссылку задают наименованием или кодом |
| `maxRows` | number |  | `40` | Сколько строк отчета вернуть |
| `offset` | number |  |  | Сколько первых непустых строк отчета пропустить |
