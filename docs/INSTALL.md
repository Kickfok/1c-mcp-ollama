# Установка и проверка

## Требования

| Компонент | Версия |
|---|---|
| Платформа 1С:Предприятие | 8.3.14 и новее (режим совместимости расширения 8.3.14). Проверено на 8.3.27.2214 |
| Конфигурация | любая с русским вариантом встроенного языка; БСП и БТС не нужны |
| Веб-сервер | Apache 2.4 или IIS с модулем расширения веб-сервера 1С |
| Python | 3.10 и новее (только для оркестратора) |
| Ollama | с моделью `qwen2.5-coder:32b` или другой (только для оркестратора) |

## 1. Расширение

### Через интерфейс

1. "Администрирование" - "Печатные формы, отчеты и обработки" - "Расширения" (в конфигурациях без БСП:
   "Все функции" - "Стандартные" - "Управление расширениями конфигурации").
2. "Добавить из файла" - `MCP_Сервер.cfe`.
3. Решите, нужен ли безопасный режим (флажок в карточке расширения):

   | Функция | Безопасный режим включен | Выключен |
   |---|:---:|:---:|
   | HTTP-сервис MCP, все инструменты и ресурсы | ✅ | ✅ |
   | Форма "Анализ конфигурации MCP": вопрос оркестратору (исходящий HTTP-запрос) | ❌ | ✅ |
   | Форма: автозапуск Ollama и оркестратора (запуск процессов, COM, запись файла) | ❌ | ✅ |
   | `get_report_list` с `includeParameters`: подключение внешних отчетов | ❌ | ✅ |

   В безопасном режиме платформа запрещает конструктор `HTTPСоединение`, поэтому форма показывает
   сообщение о безопасном режиме вместо ответа. Если нужен только MCP-сервер для внешних клиентов
   (оркестратор, Cursor, Claude Desktop), оставьте безопасный режим включенным: расширение тогда не
   может запускать программы, обращаться к файлам сервера и к сети.
4. Перезапустите сеанс 1С.

### Пакетный режим Конфигуратора

```powershell
1cv8.exe DESIGNER /F"C:\Bases\MyBase" /LoadCfg "MCP_Сервер.cfe" -Extension MCP_Сервер
1cv8.exe DESIGNER /F"C:\Bases\MyBase" /UpdateDBCfg -Extension MCP_Сервер
# только если нужен автозапуск из формы или параметры внешних отчетов:
ibcmd.exe infobase config extension update --db-path="C:\Bases\MyBase" --name="MCP_Сервер" --safe-mode=no
```

Из исходников вместо `.cfe`: `/LoadConfigFromFiles "src\extension" -Extension MCP_Сервер`.

## 2. Права

Роль `mcp_ОсновнаяРоль` дает право `Использование` на методы HTTP-сервиса и на обработки расширения,
`Просмотр` - на обработки с формами и подсистему "MCP-сервер". Назначьте роль пользователю, под
которым работает публикация, и пользователям, которые открывают обработку "Анализ конфигурации MCP".
Без нее пользователь без полных прав получит отказ в доступе.

## 3. Публикация HTTP-сервиса

HTTP-сервисы расширений **не публикуются** настройкой `publishByDefault="true"`: сервис нужно
перечислить в `default.vrd` явно. Без этого любой адрес `.../hs/...` отвечает `404`.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<point xmlns="http://v8.1c.ru/8.2/virtual-resource-system"
       xmlns:xs="http://www.w3.org/2001/XMLSchema"
       xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
       base="/mybase"
       ib="File=&quot;C:\Bases\MyBase&quot;;">
    <httpServices publishByDefault="true">
        <service name="mcp_APIBackend" rootUrl="mcp" enable="true"
                 reuseSessions="autouse" sessionMaxAge="20" poolSize="10" poolTimeout="5"/>
    </httpServices>
</point>
```

В Конфигураторе то же самое: "Администрирование" - "Публикация на веб-сервере" - вкладка
"HTTP-сервисы" - отметьте `mcp_APIBackend`.

Если в базе есть пользователи, публикация должна входить под пользователем с ролью
`mcp_ОсновнаяРоль` (атрибуты `usr` и `pwd` в `default.vrd` либо аутентификация операционной системы).
Учитывайте, что учетные данные в `default.vrd` хранятся открытым текстом.

> [!IMPORTANT]
> Регистр имени публикации в адресе должен совпадать с `base` в `default.vrd`: при несовпадении
> веб-сервер отвечает перенаправлением, и POST-запрос превращается в GET.

## 4. Проверка сервера

```powershell
curl http://localhost/mybase/hs/mcp/health
# {"status": "ok"}

python tests/mcp_smoke.py http://localhost/mybase/hs/mcp
```

`mcp_smoke.py` выполняет `initialize`, `tools/list`, `resources/*`, `prompts/list` и вызывает несколько
инструментов, включая вызовы с ошибочными аргументами. Ожидаемый результат на конфигурации без
отчетов 1С:Розницы:

```
tools/list: 21 tools
  Инструмент: Данные по продажам: list_sale_param, ...
  Данные о конфигурации (инструмент): list_metadata_objects, ...
  Инструмент: Для бухгалтерской работы: get_account_turnovers, ...
call get_configuration_version: isError=False -> { "ИмяСвойства": "ВерсияПлатформы", ... }
call list_sale_param: isError=True -> ... Не найден подходящий отчёт для получения чеков ...
unknown method: -32601 Неизвестный метод: unknown/method
```

Если `tools/list` возвращает ошибку, откройте журнал регистрации: сбой отдельной обработки-контейнера
записывается событием `MCP-сервер.Контейнеры`, а инструменты остальных контейнеров остаются доступны.

## 5. Оркестратор

```powershell
ollama pull qwen2.5-coder:32b
pip install -r orchestrator/requirements.txt
$env:MCP_URL = "http://localhost/mybase/hs/mcp"
python orchestrator/LLM_Orchestrator.py
```

При запуске оркестратор опрашивает `tools/list` и выводит инструменты по контейнерам. Если список пуст,
проверьте `MCP_URL` и раздел 4.

Первый запрос после запуска медленный: модель загружается в видеопамять (на RTX 5070 12 ГБ около
минуты). Простой вопрос с одним вызовом инструмента занимает 1-2 минуты.

Если Ollama отвечает `llama runner process has terminated: CUDA error`, модели не хватает видеопамяти
при автоматическом подборе слоев. Задайте число слоев явно, для 32B-модели на 12 ГБ - 24:

```powershell
$env:OLLAMA_NUM_GPU = "24"
```

### Монитор

`http://127.0.0.1:9000/monitor` показывает работу оркестратора: запросы, каждый шаг модели с временем
и заполнением контекста, вызовы инструментов 1С с аргументами, ответы инструментов и итоговый JSON.
Тема переключается кнопкой в шапке. Ключ `--monitor` открывает монитор отдельным окном сразу после
запуска (режим приложения Edge или Chrome):

```powershell
python orchestrator/LLM_Orchestrator.py --monitor
```

## 6. Обработка "Анализ конфигурации MCP"

Форма отправляет вопрос оркестратору на `localhost:9000` в фоновом задании и раз в секунду читает
журнал оркестратора: пока модель работает, справа видны ее шаги и вызовы инструментов 1С, затем
ответ. Данные из `Result` выводятся таблицами и списками. Переключатель "Показывать ход выполнения"
скрывает журнал шагов, кнопка "Монитор оркестратора" открывает монитор в браузере. На стартовом
экране примеры вопросов: нажатие на пример сразу отправляет его.

Если фоновое задание запустить нельзя, форма ждет ответа в том же вызове и показывает ход выполнения
после ответа. Причина записывается в журнал регистрации событием `MCP.ВопросКLLM`.

Если Ollama или оркестратор не запущены и безопасный режим расширения выключен, форма запускает их
сама и просит повторить запрос через 1-2 минуты:

- Ollama: `%LOCALAPPDATA%\Programs\Ollama\ollama.exe serve`;
- оркестратор: макет `LLM_Orchestrator` выгружается в `C:\llm_orchestrator\LLM_Orchestrator.py`,
  выполняются `pip install requests` и `python LLM_Orchestrator.py --monitor`.

Запуск выполняется на стороне **сервера 1С** (`&НаСервере`), поэтому работает в файловом варианте
базы, где сервер и клиент - один компьютер. В клиент-серверном варианте процессы запустились бы на
сервере 1С от имени его службы: запустите Ollama и оркестратор вручную на нужном компьютере.
Оркестратор, запущенный формой, использует `MCP_URL` по умолчанию; чтобы указать свою публикацию,
задайте переменную окружения `MCP_URL` для пользователя Windows.
