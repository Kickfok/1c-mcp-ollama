# Установка и проверка

## Требования

| Компонент | Версия |
|---|---|
| Платформа 1С:Предприятие | 8.3.14 и новее (режим совместимости расширения 8.3.14). Проверено на 8.3.27.2214 |
| Конфигурация | на БСП 3.1 и новее (проверено на 1С:Комплексная автоматизация 2, БСП 3.1.11): ключи хранятся в безопасном хранилище БСП, права и пользователи - средствами БСП |
| Веб-сервер | Apache 2.4 или IIS с модулем расширения веб-сервера 1С |
| Python | 3.10 и новее (только для оркестратора) |
| Ollama | с моделью `qwen2.5-coder:32b` или другой (только для оркестратора) |

## 1. Расширение

### Через интерфейс

1. "Администрирование" - "Печатные формы, отчеты и обработки" - "Расширения".
2. "Добавить из файла" - `MCP_Сервер.cfe`.
3. Снимите флажок "Безопасный режим" в карточке расширения:

   | Функция | Безопасный режим включен | Выключен |
   |---|:---:|:---:|
   | HTTP-сервис MCP: `initialize`, `tools/list`, ресурсы | ✅ | ✅ |
   | Проверка прав пользователя по токену `X-MCP-Token`, безопасное хранилище ключей | ❌ | ✅ |
   | Форма вопроса и настройки: обращение к оркестратору (исходящий HTTP-запрос) | ❌ | ✅ |
   | `get_report_list` с `includeParameters`: подключение внешних отчетов | ❌ | ✅ |

   В безопасном режиме платформа запрещает привилегированный режим и конструктор `HTTPСоединение`.
   Диагностика в настройках (раздел 6) показывает безопасный режим отдельной проверкой.
4. Перезапустите сеанс 1С.

### Пакетный режим Конфигуратора

```powershell
1cv8.exe DESIGNER /F"C:\Bases\MyBase" /LoadCfg "MCP_Сервер.cfe" -Extension MCP_Сервер
1cv8.exe DESIGNER /F"C:\Bases\MyBase" /UpdateDBCfg -Extension MCP_Сервер
ibcmd.exe infobase config extension update --db-path="C:\Bases\MyBase" --name="MCP_Сервер" --safe-mode=no
```

Из исходников: `powershell -File tools/build_extension.ps1 -Infobase "C:\Bases\MyBase" -User "<пользователь>"`
(загрузка, проверка модулей и обновление базы; пароль - переменная окружения `MCP_1C_PASSWORD`).

## 2. Права

| Роль | Кому | Что дает |
|---|---|---|
| `mcp_ОсновнаяРоль` | техническому пользователю публикации HTTP-сервиса | методы HTTP-сервиса и обработки-контейнеры инструментов |
| `mcp_ИспользованиеLLM` ("Вопросы к LLM по данным базы (MCP)") | пользователям, которые задают вопросы | обработка "Анализ конфигурации MCP" и выпуск токена вопроса |

В конфигурации на БСП роли выдаются **через профиль групп доступа**: роль, назначенная пользователю
напрямую, БСП стирает при пересчете ролей (например, после обновления расширения). Создайте профиль с
ролью `mcp_ИспользованиеLLM` (и `БазовыеПраваБСП`) и группу доступа с нужными пользователями.

Инструменты проверяют права **пользователя, задавшего вопрос**: объекты, на которые у него нет права
чтения или использования, скрываются из списков, а запрос их структуры или данных отклоняется.
Ограничения доступа на уровне записей (RLS) не применяются: данные читаются сеансом пользователя
публикации.

## 3. Публикация HTTP-сервиса

HTTP-сервисы расширений **не публикуются** настройкой `publishByDefault="true"`: сервис нужно
перечислить в `default.vrd` явно. Без этого любой адрес `.../hs/...` отвечает `404`.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<point xmlns="http://v8.1c.ru/8.2/virtual-resource-system"
       xmlns:xs="http://www.w3.org/2001/XMLSchema"
       xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
       base="/mybase"
       ib="File=&quot;C:\Bases\MyBase&quot;;Usr=&quot;mcp_service&quot;;Pwd=&quot;...&quot;;">
    <httpServices publishByDefault="true">
        <service name="mcp_APIBackend" rootUrl="mcp" enable="true"
                 reuseSessions="autouse" sessionMaxAge="20" poolSize="10" poolTimeout="5"/>
    </httpServices>
</point>
```

Публикация входит под **техническим пользователем без полных прав** с ролями `mcp_ОсновнаяРоль` и
`БазовыеПраваБСП` (в БСП отметьте его как служебного). Не публикуйте сервис под администратором:
инструмент, вызванный без токена, получит все данные базы. Учетные данные в `default.vrd` хранятся
открытым текстом - ограничьте доступ к файлу.

> [!IMPORTANT]
> Регистр имени публикации в адресе должен совпадать с `base` в `default.vrd`: при несовпадении
> веб-сервер отвечает перенаправлением, и POST-запрос превращается в GET.

Описание API для Swagger: [docs/api/openapi.json](api/openapi.json). Если в базе установлено расширение
[swagger-1c](https://github.com/zerobig/swagger-1c), оно показывает сервис на странице
`/hs/swagger/index.html` (пользователю публикации нужна роль `Swag_ОсновнаяРоль`, в публикации - флажок
"Публиковать HTTP-сервисы расширений по умолчанию").

## 4. Проверка сервера

```powershell
curl http://localhost/mybase/hs/mcp/health
# {"status": "ok"}

python tests/mcp_smoke.py http://localhost/mybase/hs/mcp
```

`mcp_smoke.py` выполняет `initialize`, `tools/list`, `resources/*`, `prompts/list` и вызывает несколько
инструментов без токена (по умолчанию вызов без токена разрешен, см. раздел 6). Ожидаемый результат на
конфигурации без отчетов 1С:Розницы:

```
tools/list: 21 tools
  Инструмент: Данные по продажам: list_sale_param, ...
  Данные о конфигурации (инструмент): list_metadata_objects, ...
  Инструмент: Для бухгалтерской работы: get_account_turnovers, ...
call get_configuration_version: isError=False -> { "ИмяСвойства": "ВерсияПлатформы", ... }
call list_sale_param: isError=True -> ... Не найден подходящий отчёт для получения чеков ...
unknown method: -32601 Неизвестный метод: unknown/method
```

Если `tools/list` возвращает ошибку, откройте журнал регистрации: сбой отдельной обработки-контейнера
записывается событием `MCP-сервер.Контейнеры`, а инструменты остальных контейнеров остаются доступны.

## 5. Оркестратор

```powershell
ollama pull qwen2.5-coder:32b
pip install -r orchestrator/requirements.txt
python orchestrator/LLM_Orchestrator.py --config orchestrator/LLM_Orchestrator.config.json
```

При первом запуске оркестратор создает ключи - **ключ клиента** (`client_key`, им 1С задает вопросы) и
**ключ администратора** (`admin_key`, вход в монитор и общий журнал), записывает их в файл конфигурации
и один раз печатает в консоль. Остальные настройки задаются в том же файле (или переменными окружения
с именами из скобок):

```json
{
  "client_key": "создается при первом запуске",
  "admin_key": "создается при первом запуске",
  "mcp_url": "http://localhost/mybase/hs/mcp",
  "ollama_model": "qwen2.5-coder:32b",
  "ollama_num_gpu": 24,
  "host": "127.0.0.1",
  "port": 9000,
  "tls_cert": "",
  "tls_key": ""
}
```

| Поле (переменная) | Назначение |
|---|---|
| `mcp_url` (`MCP_URL`) | Адрес HTTP-сервиса `mcp_APIBackend` |
| `mcp_verify_ssl` (`MCP_VERIFY_SSL`) | Проверять TLS-сертификат публикации |
| `ollama_url`, `ollama_model` (`OLLAMA_URL`, `OLLAMA_MODEL`) | API Ollama и модель |
| `ollama_num_gpu` (`OLLAMA_NUM_GPU`) | Число слоев модели на видеокарте; пусто - подбирает Ollama. Для 32B на 12 ГБ: `24` |
| `host`, `port` (`ORCHESTRATOR_HOST`, `ORCHESTRATOR_PORT`) | Адрес и порт оркестратора |
| `client_key`, `admin_key` (`ORCHESTRATOR_CLIENT_KEY`, `ORCHESTRATOR_ADMIN_KEY`) | Ключи, не короче 32 символов |
| `tls_cert`, `tls_key` (`ORCHESTRATOR_TLS_CERT`, `ORCHESTRATOR_TLS_KEY`) | Сертификат и ключ PEM: оркестратор принимает только HTTPS |

Без ключа оркестратор отвечает только на `GET /health` (`{"status": "ok"}`) и отдает страницу монитора.
Если он слушает сетевой адрес, задайте `tls_cert` и `tls_key`: иначе ключ и вопросы идут по сети
открытым текстом. Файл конфигурации содержит ключи - храните его так, чтобы его читал только
пользователь, под которым работает оркестратор.

Первый запрос после запуска медленный: модель загружается в видеопамять (на RTX 5070 12 ГБ около
минуты). Простой вопрос с одним вызовом инструмента занимает 1-2 минуты. Если Ollama отвечает
`llama runner process has terminated: CUDA error`, задайте число слоев явно (`ollama_num_gpu`).

### Монитор

`http://127.0.0.1:9000/monitor` показывает работу оркестратора: запросы с именами пользователей 1С,
шаги модели, вызовы инструментов и ответы. Монитор спрашивает **ключ администратора**; ключ запуска
`--monitor` открывает монитор отдельным окном и входит в него сам по одноразовому билету.

### API оркестратора

| Адрес | Ключ | Назначение |
|---|---|---|
| `POST /requests` | клиента | Вопрос: `{"text", "user", "mcp_token"}`, сразу возвращает `request_id` |
| `GET /requests/{id}` | клиента | Состояние вопроса и ответ (`Success`, `Text`, `Result`) |
| `POST /requests/{id}/cancel` | клиента | Отмена после текущего шага модели |
| `GET /events?request={id}&since=N` | клиента | Ход выполнения своего вопроса; без `request` - только с ключом администратора |
| `POST /` | клиента | Синхронный вопрос: ответ вместе с ходом выполнения (`Trace`) |
| `POST /diagnostics` | клиента | Ollama, связь с MCP, сквозной вызов инструмента с токеном |
| `GET /health` | любой | Без ключа - `status`; с ключом - модель, Ollama, MCP, TLS, версия |
| `GET /requests`, `GET /monitor` | администратора | Все вопросы, монитор |

Ключ передается заголовком `Authorization: Bearer <ключ>`. Токен пользователя 1С (`mcp_token`) оркестратор
добавляет заголовком `X-MCP-Token` к каждому вызову инструмента этого вопроса и никуда не записывает.

## 6. Настройки в 1С

Откройте обработку "Анализ конфигурации MCP" - кнопка **"Настройки"** (видна пользователю с полными
правами):

- **Оркестратор**: адрес (`http://127.0.0.1:9000` или `https://сервер:9000`) и ключ - `client_key` из
  файла конфигурации оркестратора. Ключ хранится в безопасном хранилище БСП и на форму не выводится.
- **Доступ к MCP**: адрес публикации, флажок "Разрешить вызов инструментов без токена" (по умолчанию
  включен - снимите его, когда все клиенты получат токены), срок токена вопроса.
- **Локальный режим**: пользователи, которым разрешено запускать Ollama и оркестратор на своем
  компьютере (включает сам пользователь в "Мои настройки").
- **Персональные токены** для внешних MCP-клиентов (Cursor, Claude Desktop): токен работает с правами
  выбранного пользователя, показывается один раз, отзывается из списка. Клиент передает его заголовком
  `X-MCP-Token`.
- **Диагностика**: 10 проверок - права, безопасный режим, ключ, доступность оркестратора, ключ принят,
  Ollama и модель, связь оркестратора с MCP, сквозной вызов инструмента с токеном, защита канала,
  пользователь публикации. У каждой ошибки - подсказка, что исправить.

## 7. Форма вопроса (1.2.0-beta)

Форма отправляет вопрос оркестратору по адресу и ключу из настроек, с токеном текущего пользователя, в
фоновом задании и раз в секунду читает ход выполнения. Данные из `Result` выводятся таблицами и
списками, на стартовом экране - примеры вопросов.

> [!NOTE]
> Переделка формы под два режима (серверный и локальный с автозапуском из тонкого клиента) - в
> следующей версии. В 1.2.0-beta автозапуск из формы еще прежний: оркестратор выгружается в
> `C:\llm_orchestrator\` и запускается без вашего файла конфигурации, поэтому при первом запуске создает
> свои ключи в `C:\llm_orchestrator\LLM_Orchestrator.config.json`. Скопируйте оттуда `client_key` в
> "Настройки" (адрес `http://127.0.0.1:9000`) - дальше автозапуск будет использовать тот же файл и ключ.
> Либо запускайте оркестратор вручную со своим `--config`.
